# hxwl-09 半导体洁净室巡检

在线粒子计数器 → 采样任务合并 → 阈值评估 → 异常工单 → 签认/审计 的完整链路看板。

## 技术栈

React 19 + Vite + TypeScript（纯前端内存状态 + localStorage 本机待补传，无后端依赖）

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5109
npm test         # 领域链路不变量断言（32 条）
npm run typecheck
npm run build
```

## 链路规则（领域代码 `src/domain/`）

1. **读数带设备序号和阈值版本**：每条在线读数带 `deviceSn + seq` 与固件戳记版本
   `stampedVersion`，以及实际判定版本 `basisVersion`（`types.ts` / `engine.ts`）。
2. **同一序号重发不生成第二张异常工单**：幂等键 `设备#序号`（补录用 `draft#id`）。
   乱序到达照常入库；重发只记一条 `duplicate` 事件（`ingestPacket`）。
3. **计数器归零开新片段**：`reset` 报文开启新 `Segment`，新片段计数从小开始；
   段内（序号更小的最近读数）计数下降只打 `dropChannels` 事实标记，**不算异常、不开工单**。
4. **黄光区断网补录**：草稿先写本机 `localStorage`（`src/io/outbox.ts`）；
   保存失败保留在表单并提示。恢复网络后“补传合并”按 **房间 × 班次 × 日期** 汇入同一采样任务，
   任务来源标记 `online / manual / merged`。
5. **阈值改版**：厂务发布新版本后，**待复核**读数立即按新版本重算 verdict/超限通道；
   工单随之撤销/补开/重开，但同幂等键永远只有一张，且已关闭工单不翻案。
   **已签认**结果的 `basisVersion` 冻结，永远保留当时依据；签认后同房间再来新事实另开待复核任务。
6. **角色权限**：班组长只能签认本班次房间任务；审计员只读事实；
   工程师发布阈值、处置关闭工单。签认/重算/开撤单全部进入事件日志与工单审计轨迹。

## 预置演示场景（`src/domain/scenario.ts`）

#101 正常 → #118 超限开单 → #118 乱序重发两次被幂等拦截 → #120 先到/#119 后到（段内下降）
→ 黄光区断网补录达标读数并按房间合并 → 白班 CR-1201 签认冻结 → 审计员/夜班组长越权被拒
→ 计数器归零开新片段 → #118 工单关闭 → 发布 v2（ISO 6 · 0.5µm 10200→9000）：
待复核读数重算（#119/补录/#2 新超限），已签认 CR-1201 保留 v1 → 夜班读数。

页面右上可切换角色、切换“断网”，并用录入区亲手模拟重发、归零、补录与补传。
